# 大模型能力边界（D5）

> 一句话结论：大模型是**按概率生成文本的引擎**，不是数据库、不是计算器、也不是搜索引擎。

## 二、我实测的数字（deepseek-chat，2026-11-22）

### 1. token 不是字数

| 样本 | 字符数 | token | 字符/token |
|---|---:|---:|---:|
| 中文 ×1 | 35 | 25 | 1.40 |
| 中文 ×5 | 175 | 97 | 1.80 |
| 中文 ×20 | 700 | 367 | 1.91 |
| 中文 ×80 | 2800 | 1447 | 1.94 |
| 英文 ×1 | 79 | 19 | 4.16 |
| 英文 ×20 | 1580 | 266 | 5.94 |

结论：中文约 **1.9 字/token**，英文约 **6 字符/token**。同样的信息量，中文贵 3 倍左右。tokenization 是确定性的——同一段文本，跑多少次切出的 token 数都一样。

### 2. 一次真实问答的账

- 提问 23 token → 回答 266 字 / 156 token，1.79 秒，0.001294 元
- **输出占全部 token 的 87%**
- 输出速度约 87 token/秒
- 一次问答 0.0013 元 → 1000 次约 1.3 元，30 条测试集跑一遍几分钱

### 3. 长上下文的代价

- 我的《AI 学习笔记-第1-4天》：31,353 字符 → **13,485 token**，整本塞进上下文一次 0.027 元，问 100 次 2.70 元
- 推算：300 页设备手册约 24 万字 ≈ 12.6 万 token，一次问答输入就 0.25 元，而其中 95% 与问题无关

**这就是 RAG 的经济学理由**：不是模型记不住，是没必要为无关内容付费，也没必要让模型在噪声里找答案。

### 4. 温度与幻觉

温度（同一个问题问 3 次，看第一行名字有几种）：

| 温度 | 我的结果 | 第二次运行 |
|---|---|---|
| 0 | 1 种 | 1 种 |
| 0.7 | 3 种 | 2 种 |
| 1.3 | 2 种 | 3 种 |

结论：3 个样本连"温度越高越分散"都测不稳；温度 0 也不保证 100% 确定。

幻觉三连（裸问 vs 加"不知道就说不知道"约束）：

| 问题 | 裸问 | 加约束 |
|---|---|---|
| 虚构国标 GB/T 41234-2025 | 拒答，说需要正式文本 | 更干脆地拒答 |
| 2026-11 的新模型 | 拒答，说知识有截止 | 拒答 + 说明缺什么 |
| 私有设备 ACS880 F0009 | **编造**：一次说"直流母线欠压"并给参数号，另一次说"逆变单元过温" | 承认不知道，并列出需要的信息 |

**判据：知识是可重复的，编造是不可重复的。关键事实问 3 次，答案不一致就不可信。**

## 三、提示词 / RAG / 微调：三道闸门

```
第 1 问：模型会做这件事吗？
   ├─ 不会（它不知道我们厂的设备手册）─────────────► RAG
   └─ 会，但输出不合要求
          │
第 2 问：只是格式 / 风格 / 边界不对吗？
   ├─ 是 ────────────────────────────────────► 提示词
   └─ 不是，有几百条标注样本，且提示词调到头了 ──► 微调
```

| | 解决什么 | 成本 | 迭代周期 |
|---|---|---|---|
| 提示词 | "怎么说"：格式、角色、约束、边界 | 几乎零 | 分钟 |
| RAG | "知道什么"：私有 / 新 / 长文档 | 中 | 天 |
| 微调 | "怎么反应"：风格、术语、格式稳定性 | 高 | 周 |

三个关于微调的误区：

- 别用微调注入知识（知识会变，更新要重训）→ 要知识用 RAG
- 样本少于几百条基本无效（十来个例子用 few-shot 就够）
- 微调不降低推理成本，它只让模型"更像你要的那个模型"
